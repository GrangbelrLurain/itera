# 패키지 가격 계산 규칙

판매가는 저장하지 않고 **원가 구성 + 마진**에서 계산한다. 예약 시점에 계산 결과를 스냅샷으로 저장한다.
(1단계 구조 작업에서는 아래 계산기를 `PriceCalculator` 인터페이스 뒤에 두고, 임시로 상품 기본 가격을 그대로 쓴다.)

## 1. 계산 순서 (대상 구분별: 성인, 소아(노베드), 소아(엑스트라베드), 유아)

```
① 원가            = 원가 구성 항목(항공, 호텔, 현지, 관광, 보험, 기타)의 합
② 마진 적용 금액    = ① + ① × 마진율 + 고정 마진          (마크업, 정수 연산)
③ 판매가           = ② 를 100원 단위로 절삭              (100원 미만 버림)
④ 할인 후 판매가    = max(0, ③ − 할인액)
⑤ 통과 항목        = 유류할증료 + 제세공과금              (원가 그대로, 마진·수수료 대상 아님)
⑥ 고객 결제액      = ④ + ⑤
⑦ 수수료           = ④ × 수수료율  (또는 고정 수수료), 100원 단위 절삭, 최대 ④까지
⑧ 회사 순수익      = ④ − ① − ⑦
```

| 결정 | 내용 |
|---|---|
| 마진 | **마크업**: 원가 대비 비율(`마진율 %`) 또는 고정금액(1인당), 둘 다 설정하면 합산 |
| 절삭 | 계산된 금액은 모두 **100원 미만 절삭**(③, ⑦). 정수 나눗셈의 원 단위 버림은 최종 100원 절삭과 결과가 같아서(`⌊⌊x⌋/100⌋ = ⌊x/100⌋`) 별도 반올림 단계가 필요 없다 |
| 유류할증료·제세공과금 | **통과 항목**: 마진 계산 대상이 아니고 수수료 기준에도 들어가지 않는다 |
| 수수료 기준 | **할인 후 판매가(④) 전체**. 마진에서 떼는 것이 아니라 판매가에서 떼며, 회사 마진과 별개로 나간다 |
| 수수료 방식 | 비율(%) 또는 1인당 고정금액 |
| 채널 | **채널 코드**로만 구분한다(예: `DIRECT`, `AGENCY_A`). 대리점 개체·계정은 만들지 않는다 |

> 수수료 기준을 "통과 항목까지 포함한 고객 결제액(⑥)"으로 바꾸려면 ⑦의 기준만 ⑥으로 바꾸면 된다.

## 2. 정수 연산

비율은 **bp(1/100 %)** 정수로 저장한다 (10% = 1000bp, 2.5% = 250bp). 부동소수점을 쓰지 않는다.

```
마진 적용 금액 = 원가 + 원가 × margin_bp / 10000 + margin_fixed     (원가 × margin_bp 는 long)
판매가         = (마진 적용 금액 / 100) * 100                         (정수 나눗셈 = 절삭)
수수료         = min(할인 후 판매가, 할인 후 판매가 × commission_bp / 10000) 를 100원 단위 절삭
```

### 예
원가 1,000,000 / 마진 12% / 고정 마진 0 / 할인 50,000 / 유류 90,000 / 세금 45,000 / 수수료 8%
- ② 1,000,000 + 120,000 = 1,120,000 → ③ 1,120,000
- ④ 1,070,000, ⑤ 135,000, ⑥ 1,205,000
- ⑦ 1,070,000 × 8% = 85,600 → **85,600** (100원 미만 없음)
- ⑧ 1,070,000 − 1,000,000 − 85,600 = **−15,600** (할인이 마진보다 크면 음수가 될 수 있다: 경고 대상)

원가 833,333 / 마진 10% → ② 916,666.3 → ③ **916,600**

## 3. 데이터 모델 (가격 단계에서 추가)

```
product_cost_component   (product, component_type, target_type, cost)      원가 구성
product_pricing_policy   (product, margin_bp, margin_fixed, round_unit=100) 마진 정책
departure_cost_override  (product, date, component_type, target_type, cost, note) 날짜별 원가 덮어쓰기
channel_commission       (channel_code, product 또는 전체, commission_bp 또는 fixed)
```

수수료 정책 우선순위: **상품 + 채널** → **채널** → 없음(0). `DIRECT` 채널은 기본 수수료 0.

## 4. 예약 스냅샷

예약의 여행자 행에 **예약 시점 값**을 저장한다.

`unit_cost`, `unit_margin`(③ − ①), `unit_sale_price`(③), `unit_discount`, `unit_pass_through`(⑤), `unit_commission`(⑦), `channel_code`, `unit_total`(⑥)

이후 정책이 바뀌어도 이미 받은 예약의 정산 값은 변하지 않는다.

## 5. 구현 상태

| 항목 | 구현 |
|---|---|
| 계산 | `PricingRules`(정수 연산: 판매가, 수수료) + `CostBasedPriceCalculator`(`PriceCalculator` 구현) |
| 원가 구성 | `product_cost_component` — 대상 구분에 원가 행이 있으면 그 구분은 원가 기반, 없으면 `product_price.base_price`(수동 판매가) 사용 |
| 마진 | `product_pricing_policy` — `margin_bp`(마크업, bp), `margin_fixed`(1인 고정). 합산 |
| 통과 항목 | 유류할증료·제세공과금은 `product_price`의 값을 그대로 더한다 (마진·수수료 제외) |
| 수수료 | `channel_commission` — 채널 + 상품(`*` = 전체). **상품 행이 채널 전체 행보다 우선**, 비활성 행은 무시, 행이 없으면 0 |
| 예약 스냅샷 | 여행자 행에 `unit_cost`(수동 가격이면 NULL), `unit_commission`, 판매가·할인·통과 항목 저장. 이후 정책이 바뀌어도 변하지 않음 |
| 공개 API | 원가·수수료·순수익은 **내려주지 않는다** (관리자 `GET /admin/bookings/{code}` 만 `AdminBookingDetail`로 제공) |
| 관리자 화면 | 상품의 `원가 · 마진` 탭(입력 + 채널별 미리보기), `채널 수수료` 화면, 예약 상세의 원가·수수료·순수익 |

### 제한

- 날짜별 원가 덮어쓰기(`departure_cost_override`, 007)는 구현됨: 같은 (항목, 대상)이면 상품 원가를 대체하고, 없는 항목이면 그 날짜에만 원가 줄이 추가된다. 저장하면 출발 행이 생성·고정(S2)되며, 이미 만든 예약의 스냅샷은 바뀌지 않는다. 관리자 화면: 출발일 관리 → 원가 조정.
- 수동 가격이 섞인 예약은 총 원가와 순수익을 알 수 없어 표시하지 않는다(`null`).
- 할인이나 수수료가 마진보다 크면 순수익이 음수가 될 수 있다. 막지 않고 빨간색으로 표시만 한다.
